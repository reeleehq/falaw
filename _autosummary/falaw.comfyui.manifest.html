falaw.comfyui.manifest#

The deployment-manifest checker (checklist rows 1-4, 6-9, L).

A manifest is one committed file; this reads it as a dict. Two rules: a missing field is a failure, and a bare boolean is not evidence — a claim is checked against what backs it (a file digest, a pinned commit proven to sit at or after the floor tag, an allowlist of arguments). Everything the checker would have to reach for is a keyword argument: base_dir (where evidence files live), commit_floor (the git ancestry test), allowed_args and the blocked endpoint set. A wrong-typed field is a Problem, never an exception.

Limit worth knowing: a proxy config’s digest proves the file is the one the manifest names, not that it enforces client_endpoints. The endpoint lists are claims about that config until a parser for the deployment’s proxy is plugged in.

>>> from falaw.comfyui import check_manifest
>>> [str(p) for p in check_manifest({})][:1]
['2: comfyui.commit must be a 40-hex commit sha']

An allowlist, not a secret-shaped scan: /system_stats returns sys.argv, so a stray value after a flag that takes none (--cpu sk-...) is as much a leak as a --api-key flag. A bare --listen is refused by its count: in ComfyUI it means every interface.

falaw.comfyui.manifest.check_manifest(manifest, *, base_dir=None, commit_floor=None, allowed_args={'--cpu': (0, 0), '--disable-all-custom-nodes': (0, 0), '--disable-auto-launch': (0, 0), '--disable-metadata': (0, 0), '--dont-print-server': (0, 0), '--input-directory': (1, 1), '--listen': (1, 1), '--max-upload-size': (1, 1), '--output-directory': (1, 1), '--port': (1, 1), '--temp-directory': (1, 1), '--whitelist-custom-nodes': (1, 1000)}, blocked_endpoints=('/internal', '/userdata', '/v2/userdata', '/users', '/settings', '/system_stats', '/experiment'), allow_shared=False, licence_screen=None)[source]#

Problems with a deployment manifest; an empty list means it passes.

base_dir is where evidence files (proxy config, network policy) are resolved and their sha256 verified; commit_floor(commit) -> bool answers whether the commit is at or after FLOOR_TAG (see git_commit_floor()); licence_screen(names) -> LicenceScreen re-runs the screen on the pinned checkout (e.g. lambda names: screen_licences(nodes_dir, only=names)). Without them those claims cannot be verified, which is a problem, not a pass.
